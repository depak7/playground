# Contributing

Thanks for helping with this playground repo. Three things that keep changes easy to review:

1. **Keep the change small.** One focused change per pull request is easier to understand and merge.
2. **Say why.** In the commit message and PR description, explain the reason for the change, not only what files moved.
3. **Match the existing style.** Prefer short, plain text and simple shell, the same way `README.md` and `script.sh` are written.
